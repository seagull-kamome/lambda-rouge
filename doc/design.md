# lambda-rogue 設計書

- Status: Draft 1.20（M5 スライス 10 完了。浮遊中のトラップ無効を明確化）
- Date: 2026-11-13
- Target: Idris 2 0.8.0 / rc2 backend / termui 0.1.0 / rc2base 0.1.0
- Reference: Rogue 5.4.4 (Berkeley Rogue) を第一候補とする
- 関連: `doc/core-api.md`, `doc/rogue-reference.md`, `doc/persistence.md`

## 0. 要約

`lambda-rogue` は、古典的な Rogue のゲームプレイを Idris 2 と rc2 で忠実に再実装し、
画面表示・入力・演出だけを termui で現代化するターミナルローグライクである。

- ゲーム性（地形生成、モンスター、アイテム、戦闘、空腹、ターン、勝利条件）は原本に合わせる。
- UI/UX（レイアウト、色、マウス、ログ、インベントリ、ヘルプ、アニメーション）は現代風にする。
- ゲームの真実は純粋な Core に置き、termui 側はその表示と入力だけを担当する。
- 決定論的 RNG とリプレイを最初から設計に含める。

現時点の調査では、**rc2 コンパイラ本体に必須の新機能はない**。以前 P0 としていた
`termui` の Canvas と `rc2base` の純粋 RNG は、どちらもすでに実装されている。
ただし `Xoroshiro128PlusPlus.Gen` は `export data` で状態を取り出せないため、
lambda-rogue は同じアルゴリズムを `Core/Rng.idr` の純粋な状態として持つ
（rc2base の `Gen` と 100 ステップ一致することを検証済み）。残る上流の不足は
端末能力検出、64-bit 整数の JSON 表現、`Gen` の状態アクセサで、いずれも
ゲーム側のフォールバックで回避できる。詳細は
[8. rc2 / rc2base / termui の現状](#8-rc2--rc2base--termui-の現状) を参照。

## 1. ビジョンと成功条件

### 1.1 ビジョン

「1980 年代の Rogue を、2020 年代のターミナルで遊びたい」と思える作品にする。
見た目はリッチでも、判断に必要な情報は Rogue のまま。現代的な便利さが
ゲームの難易度や情報量を変えてはいけない。

### 1.2 成功条件

- 80x24 端末のクラシック表示（メッセージ 1 行 + マップ 80x22 + ステータス 1 行）と、
  120x40 以上のモダン表示の両方が成立する。
- 同じ seed とコマンド列から、常に同じゲーム状態・メッセージ・画面になる。
- 26 階層、アミュレット、死亡・勝利、セーブ・リプレイが一通り動く。
- モンスター、アイテム、地形、戦闘の全データが原本の範囲をカバーする。
- キーボードだけで全操作が完結し、マウスは追加の快適さとして使える。
- 端末幅が狭い、TrueColor でない、Unicode が使えない、といった環境で破綻しない。
- `verify.sh` が rc2 でビルド・実行・回帰テストを完走する。

### 1.3 非目標

- クラス、スキル、クエスト、店、クラフト、マルチプレイ。
- 自動探索、自動戦闘、ゲームバランスの再調整。
- 画像プロトコル（Kitty/Sixel/iTerm2）や音声再生。
- ネットワーク対戦・ランキングサーバ。
- Web 版・GUI 版。ターミナルに集中する。

## 2. 忠実性ポリシー

### 2.1 原本に合わせるもの

以下は「ゲーム性」であり、原本の仕様を再現する。

- ダンジョンの論理サイズ、部屋・通路・ドア・階段・トラップの生成。
- モンスターの種類、出現深度、能力、AI、攻撃、経験値。
- アイテムの種類、出現深度、未識別名、呪い、強化値、使用効果。
- 戦闘の命中・AC・ダメージ・装備・指輪の計算。
- 空腹、食料、休憩、探索、走る、アイテムの識別。
- ターン進行、モンスターの行動順、階層移動、アミュレット取得と帰還。
- ランダム性の範囲。UI の都合で乱数を追加・消費しない。

### 2.2 現代化するもの

以下は「見せ方」であり、ゲーム状態を変えない。

- レスポンシブな画面レイアウト、サイドバー、ミニマップ。
- TrueColor、テーマ、Unicode グリフ、ASCII フォールバック。
- メッセージログ、フィルタ、スクロールバック、重要メッセージの固定。
- インベントリの詳細表示、比較、アクション選択、検索。
- マウス、ホバー、ツールチップ、クリック、ホイール。
- コマンドパレット、ヘルプ、キーバインド変更。
- 短いアニメーション、ダメージ表示、画面遷移。
- オートセーブ、クラッシュ復旧、リプレイ、シード共有、戦績画面。
- アクセシビリティ（ASCII、高コントラスト、アニメーション無効、色以外の手掛かり）。

### 2.3 情報の非対称性を壊さない

モダン UI は「見やすくする」が「賢くする」ことはしない。

- 未探索の地形、未視認のモンスター、未知のトラップを表示しない。
- 未識別アイテムの正体、呪い、強化値を推測して表示しない。
- モンスターの正確な HP など、原本が与えない情報を追加しない。
- ツールチップは「見えている・知っている」情報だけを表示する。
- 自動探索や自動攻撃で、プレイヤーが知らない危険を踏ませない。

### 2.4 リファレンスとライセンス

- 第一候補は Rogue 5.4.4。バージョン差がある仕様は `doc/rogue-reference.md` に
  出典と観測方法を記録し、実装前に確定する。
- 原本のソースコードをコピーしない。観測した挙動、公開されている仕様、
  プレイ記録からクリーンルームで再実装する。
- データテーブル（モンスター名、アイテム名、出現表など）は手作業で転記し、
  ライセンスを確認する。配布条件が不明な素材は使わない。
- lambda-rogue 自体のライセンスは **BSD 3-Clause License** とし、全文を
  リポジトリ直下の `LICENSE` に置く。パッケージ定義の `license` も
  `BSD-3-Clause` に揃える。原本由来の著作権表示と免責事項は
  `doc/rogue-reference.md` 18 章に残す。
- テスト用の期待値は「どのリファレンスの、どの操作の結果か」を残す。

## 3. ゲーム仕様

### 3.1 1 回のラン

- クラス選択なし。開始時に seed を決定し、深度 1 から始める。通常は起動時刻
  （ナノ秒）と PID から 64-bit seed を生成する。`--seed` で 16 桁の小文字 hex を
  指定すると、その seed の新しいランを開始する。
- ダンジョンは全 26 階層。最深部にアミュレットを置く。
- アミュレット取得後、地上まで帰還すると勝利。
- 死亡は確定。セーブの復元で死亡を回避できないようにする。
- ターン数、深度、経験値、殺したモンスター、取得金、死因を戦績に残す。

### 3.2 ダンジョン

- 論理マップは 80x22 とする。クラシック 80x24 端末では、1 行目をメッセージ、
  2〜23 行目をマップ、24 行目をステータスに使う。画面サイズとゲーム座標を分離する。
  これは 80x24 の実画面と、公開ヘッダの `NUMLINES=24`, `NUMCOLS=80`,
  `STATLINE=23` で裏付けられている。詳細は `doc/rogue-reference.md`。
- 3x3 の部屋スロットを使う古典的な部屋生成。部屋、通路、ドア、秘密のドア、
  トラップ、階段、暗い部屋を原本の確率・制約に従って配置する。
- 下層では、部屋の代わりに迷路が入ることがある。
- 生成後は必ず「開始地点から下り階段まで到達可能」であることを検証する。
- 階層ごとにモンスター・アイテム・金・食料を出現表に従って配置する。
- アミュレット取得まで上階へ戻れない。取得後は訪問済みの階層を逆順に昇り、
  各階層の状態を保持する。
- 水位・溶岩・採掘など、原本にない地形は追加しない。

### 3.3 ターン進行

1. プレイヤーのコマンドを受け取り、ターンを消費するか決める。
2. プレイヤーの移動・攻撃・アイテム使用・探索などを解決する。
3. モンスターの行動を解決する。
4. 状態異常、空腹、再生、呪い、タイマーを進める。
5. 視界と探索済みマップを更新する。
6. メッセージ、死亡、勝利、階層移動を判定する。

- 移動・攻撃・使用・探索は原則 1 ターン。
- インベントリを開く、ヘルプを見る、カーソルを動かすなどはターンを消費しない。
- 「走る」「休む」など、原本にある継続行動は途中で危険を検知したら止まる。
- UI のアニメーションはターン解決後に再生し、ゲーム状態を変更しない。

### 3.4 視界と探索

- 部屋の明かり、通路の視界、暗い部屋を原本の挙動に合わせる。
- 視線判定はグリッド上の LOS で行い、壁・ドア・モンスターで遮る。
- `explored` は `Level` に保持する。`visible` は各ターンの終わりに FOV から
  計算する一時的なビットグリッドであり、`Level` の永続状態には含めない。
- 探索済みだが不可視の地形は暗く表示し、不可視のモンスター・アイテムは表示しない。
- モダン UI でも、視界外の情報をミニマップやツールチップに出さない。

### 3.5 モンスター

- A-Z の 26 種類を原本のデータで実装する。
- 深度ごとの出現帯（公開 5.4.4 シートの `上`/`下`、帯内は等確率）、睡眠、
  起きる条件、逃走、追跡、特殊能力を再現する。群れは未実装（17 章）。
- モンスターごとの能力例: 毒、麻痺、混乱、盲目、ホールド、炎/冷気、
  ドレイン、装備破壊、アイテム窃取、再生、魔法使いの遠遠攻撃。
- AI は原本の追跡・移動規則を再現する。現代的な A* や完全情報の判断を
  追加して難易度を変えない。
- モンスターは ID で参照し、UI のアニメーションやログが同じ個体を追えるようにする。
- M4 スライス 2 で A-Z 26 種の列挙・名前・グリフを実装し、スライス 12 の
  忠実性監査でレベル・AC・攻撃・経験値・HP・出現深度を 5.4.4 の公開表に
  置き換えた。最終値は `doc/rogue-reference.md` 4 章を参照する。
- 特殊能力は `MonsterAbility` の集合として `MonsterSpec` に持たせる。毒、混乱の
  視線、ホールド、炎、遠距離攻撃、ドレイン、装備の錆、金/アイテム窃取、再生、
  透明、不規則移動、不動、2 回行動、通常睡眠、強欲、物体擬態を実装した。
  命中時の能力はダメージ解決後に固定順で 1 つだけ適用する。強欲と物体擬態は
  現状フラグのみで、AI・表示への反映は 17 章の残課題とする。
- 透明なモンスターは隣接するか、プレイヤーが「見えざるものを見る」状態
  （薬・巻物・指輪）のときだけマップとサイドバーに表示する。
- モンスターが盗んだアイテムは `ItemLocation.CarriedBy` で個体に紐づけ、
  そのモンスターが死んだときに最後の位置へ落とす。

### 3.6 アイテム

- 武器、防具、食料、ポーション、巻物、杖、指輪、金、アミュレット。
- 出現深度、呪い/祝福、強化値、充填数、数量を原本の表に従って決める。
- 未識別名（ポーションの色、巻物の題名など）はランごとにランダム化する。
- M4 スライス 1 で巻物 18 種、杖 14 種、指輪 14 種を追加した。スライス 12 の
  監査で、光の杖だけ 10–19 充填、それ以外は 3–7 充填に修正した。1 回の振りで
  1 充填を消費する。指輪は左右 2 枠まで装備できる。
- 外見（ポーションの色、巻物の題名、杖・指輪の材質名）は `Game.appearances` に
  ランの開始時に 1 回だけシャッフルして保存する。同じランでは同じ種別が同じ外見、
  別の seed では別の対応になる。固定フィクスチャは従来の固定外見表にフォールバックする。
- 投げるは装備中の物を除く所持品に使える。武器は対象にダメージ、ポーションは
  割れて消え、それ以外は床に落ちる。対象がいなければ方向の先の床に落ちる。
- インベントリは a-z の表示スロットを持つが、同時所持数は原本の上限 23 に従う
  （公開ヘッダの `MAXPACK=23`。実機での追確認は M2 で行う）。
  表示スロットが 26 個あっても、所持できるのは 23 個までとする。
- 装備、外す、投げる、落とす、食べる、飲む、読む、振る、拾う、識別する。
- 識別状態はラン内で保持し、セーブ・リプレイに含める。
- UI は未識別の正体を漏らさず、既知の効果だけを詳細に表示する。

### 3.7 戦闘と成長

- 攻撃は原本の命中判定、AC、レベル、能力値、武器/防具の強化、指輪を反映する。
- ダメージは武器・モンスターごとのダイスで計算する。
- 経験値、レベルアップ、最大 HP、命中率の上昇を原本に合わせる。
- 装備の呪い、外れない装備、強化値、AC の計算を再現する。
- 計算式は `Combat.idr` に集約し、期待値を `doc/rogue-reference.md` とテストで固定する。

### 3.8 空腹・状態異常・タイマー

- ターン経過による空腹、食料による回復、飢餓ダメージ。
- 毒、麻痺、混乱、盲目、ホールド、加速、減速、再生、ドレイン、
  テレポート、魔法の地図などの効果と持続ターン。
- M4 スライス 1 で食料感知、透明、ホールド、減速、麻痺、恐怖、睡眠を追加した。
  睡眠の巻物は `Asleep` と `Sleeping` を同時に付与し、直後の起床判定で
  即座に起きないようにする。スライス 12 で睡眠の巻物の対象が原本と異なる
  ことを確認し、既知の相違として記録した（`doc/rogue-reference.md` 17.2）。
- M4 スライス 2 で睡眠・熊・錆・不思議のトラップ効果を実装した。スライス 12 で
  睡眠 `Sleeping 6`、熊 `Held 4`（適用ターン終了時に 1 減るため実効 5 / 3 行動）、
  不思議はメッセージのみに修正した。錆は装備中の防具の強化値を 1 下げ、
  保護または維持の指輪があれば防ぐ。
- プレイヤーの `Sleeping` / `Paralyzed` は全行動を飛ばして 1 ターン消費する。
  `Held` は移動を封じるが、隣接モンスターへの攻撃は許可し、移動を試みた
  ターンは消費する。
- モンスターも同じ `Status` を持ち、ホールド/減速/麻痺/睡眠は行動を飛ばし、
  混乱はランダム移動、恐怖は逃走、加速は 2 回行動として解決する。
- 効果は `Status` の集合として持ち、UI はアイコン・色・残りターンを表示する。
- 状態異常の解決順序を固定し、リプレイで同じ結果になるようにする。

### 3.9 勝利・死亡・戦績

- HP 0 で死亡。死因、深度、ターン、装備、所持金、殺害数を表示する。
- アミュレットを持って深度 1 の上り階段に到達すると勝利。
- 戦績はローカルに保存し、スコア順に表示する。
- 死亡時・勝利時にアクティブセーブを削除し、復活できないようにする。

### 3.10 コマンド

- 原本のキー操作を第一級にする（vi キー、矢印キー、テンキー、階層移動、
  拾う、装備、使用、投げる、探索、休む、走る、ヘルプなど）。
- すべてのコマンドにキーボードショートカットを用意する。マウスは必須ではない。
- モダン UI 用に F キー、コマンドパレット、メニューバー、クリック操作を追加する。
- キーバインドは設定ファイルで変更可能にし、ヘルプは実際の設定から生成する。
- 破壊的操作（終了、死亡確定、上書きセーブ）は確認ダイアログを出す。

## 4. アーキテクチャ

### 4.1 純粋 Core と効果 Shell

```
入力 (TermUI.Input)
        │
        ▼
  App.Update : Msg -> Model -> (Model, Cmd Msg)
        │                         │
        │                         ├─ Core.step : Command -> Game -> Outcome
        │                         │     ├─ Game'    (純粋状態)
        │                         │     ├─ Messages (ログ)
        │                         │     └─ Events   (演出用)
        │                         └─ UI 状態 (モーダル/選択/スクロール)
        ▼
  App.View : Model -> Node Msg   (純粋。canvas ノードを返すだけ)
        │
        ▼
  termui layout ── Frame ── diff ── 端末
```

- `LambdaRogue.Core.*` は `IO` も `termui` も import しない。ゲーム状態の変更は
  すべて `Core.step` を通す。UI が直接 `Game` を書き換えない。
- `Outcome` の `Events` は「誰がどこで何をしたか」の UI 向け記述であり、
  ゲーム結果には影響しない。アニメーションの有無で乱数や状態を変えない。
- `TermUI.Canvas` は IO で描画する可変リソースである。App が起動時に 1 個生成して
  保持し、`App.View` は `canvas c` を返すだけにする。`View` の中で描画しない。
- ゲーム状態が変わったら、`App.Update` が
  `Perform (drawMap c game >> pure CanvasPainted)` を返す。`Perform` は
  モデル更新後に走り、`CanvasPainted` を処理してから `view` が呼ばれる。
  1 ターン 1 回、約 1,760 セルの描画になる。
- サイドバー、ログ、ダイアログは通常の `Node` で組む。Canvas はマップ専用。
- セーブ、ロード、スコア書き込みは `App` 層の `Cmd`/`Perform`/`RunTask` で行う。
- 画面の再描画は termui の diff に任せ、ゲーム側で ANSI を出さない。

### 4.3 データモデルの方針

- 座標・HP・ターン・深度などホットな数値は `Int32`/`Bits32` を使う。
  `Nat` はリストの添字や UI の個数に限定する。`Nat` の `div`/`mod` は
  rc2 で遅いことが既知のため、乱数・距離・座標計算に使わない。
- マップは 80x22 = 1,760 セルの小さなグリッドなので、不変データのコピーで十分。
  必要なら `Data.IOArray` ではなく、純粋な `Array`/`Vect`/`List` を使う。
- `explored` は 80x22 = 1,760 bit のビットグリッド。`Bits64` の配列
  （28 ワード）または `Vect 28 Bits64` で持つ。`visible` は各ターンの終わりに
  FOV から計算し、セーブには保存しない。
- モンスター・アイテム・部屋には安定した ID を振る。UI の演出は ID を参照し、
  リストの添字に依存しない。
- 文字列の添字アクセスは rc2 では O(n)。ホットパスで `String` を
  1 文字ずつ走査しない。ログは `List String` を描画時に一度だけ連結する。

### 4.4 乱数と決定論

- Core は `LambdaRogue.Core.Rng.Rng` を持つ。中身は 128-bit の
  xoroshiro128++ 状態（`s0`, `s1` の 2 つの `Bits64`）である。
- rc2base の `System.Random.Xoroshiro128PlusPlus.Gen` は `export data Gen` で
  公開されており、構築子も状態アクセサも外から見えない。そのため `Gen` の
  128-bit 状態をセーブやリプレイに直接書くことはできない。Core では
  `Gen` を状態型として使わず、同じアルゴリズムを純粋な `Rng` 値として持つ。
- アルゴリズムは xoroshiro128++ 1.0（Blackman & Vigna、public domain）と
  splitmix64 seeding。`tests/RngTest.idr` で `fromSeed` / `next64` が
  rc2base の `mkGen` / `genNext` と 100 ステップ完全一致することを検証済み。
- seed は 64-bit。`fromSeed seed` が splitmix64 で初期状態を作る。
- ゲーム向けの `uniform`, `roll`, `chance`, `pick`, `shuffle`,
  `stateHex`, `stateFromHex` は `LambdaRogue/Core/Rng.idr` に置く。
  状態は 32 文字の小文字 hex（`s0` 16 文字 + `s1` 16 文字）で保存できる。
- 同じ seed、同じコマンド列、同じバージョンから同じ結果を保証する。
  これは lambda-rogue 内の決定論であり、原本 Rogue の乱数列との互換は非目標。
- 乱数の消費順序を固定する。UI のアニメーションや描画で乱数を消費しない。
- リプレイは「seed + 意味的コマンド列 + `gameVersion`」を基本とし、
  検証には `gameDigest` を使う。途中の状態スナップショットや
  チェックポイントは必要になった時点で追加する。
- ゲームの判定は整数の `uniform` / `roll` で行い、`Double` の丸めに依存しない。
  `Double` が必要なのは UI の揺らぎやテストだけである。
- 将来 rc2base に `genState` / `genFromState` が入ったら、`Rng` の内部実装だけを
  `Gen` に差し替えられる。呼び出し側の API は変えない。

## 5. UI / UX

### 5.1 画面レイアウト

ワイド（120x40 以上）の例:

```
┌ λRogue ─ Depth 7 ─ Seed 9f3a… ─ Turn 1240 ────────────────┐
│                                                            │
│  ########          ########                                │
│  #......#          #......#          HP  12/20  [██████░░] │
│  #..@...#  ######## #..!...#          Str 16  Int 10  Wis 8│
│  #......#  #......# #......#          Dex 14  Con 12  Cha 7│
│  ####+###  #..k...# ####+###          AC  4   Exp 123/300  │
│            #......#                   Gold 87  Food 1200   │
│            ########                   ───────────────────  │
│                                       Weapon: +2 mace      │
│                                       Armor : ring mail    │
│                                       Rings : slow digestion│
│                                       Status: Hungry       │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ > You hit the kobold.                                      │
│ > The kobold hits you.                                     │

└────────────────────────────────────────────────────────────┘
```

- ワイド（120x40 以上）: ヘッダ 1 行 + メイン 30 行 + ログ 8 行 + ステータス 1 行。
  メインは左 80 列がマップ 80x22 とその下の 36x8 ミニマップ、右 40 列が
  サイドバー。ミニマップの右には記号の短い凡例を置く。
- 80x24: 1 行目がメッセージ、2〜23 行目がマップ（80x22）、24 行目がステータス。
  サイドバーは `Tab`/`i` のオーバーレイで表示する「クラシック互換」レイアウト。
  ヘルプとコマンドパレットは 80x24 に収まるモーダルとして表示する。
- 極端に狭い場合: マップを縮小せず、「端末が小さすぎます」と必要サイズを表示する。
- 画面サイズ変更時はマップの表示位置を再計算する。マップ全体が収まるので、
  M1 ではカメラ移動を入れない。ズーム/縮小を入れる場合だけ App 側で座標変換し、
  ゲーム座標は変えない。

### 5.2 マップ表示

- 地形、モンスター、アイテム、トラップ、プレイヤーをセル単位で描く。
  `TermUI.Canvas` の `clear` → `putCell` で 80x22 を描き、`canvas` ノードで出す。
  Canvas は結合文字を持たないので、マップのグリフは幅 1 の文字だけを使う。
- クラシック ASCII セットとモダン Unicode セットを切り替え可能にする。
- ASCII セットは Rogue の記号を尊重し、Unicode セットでも情報の意味を変えない。
- 壁・床・ドア・階段・トラップ・未探索は、色だけでなく形でも区別する。
- 視界内は明るく、探索済みは暗く、未探索は空白。
- プレイヤー、モンスター、アイテム、ターゲット、カーソルに明確なスタイルを付ける。
- ホバー中のセルを強調し、判明している情報だけをツールチップに出す。
  スライス 6 では `Game.hover` を `App.Model.hover` に持ち、`MapView.describeCell`
  が未探索なら何も出さず、探索済みなら地形と、見えているモンスター・アイテム・
  発見済みトラップだけを最新メッセージ行に出す。強調は Inverse 属性で行う。
- ミニマップは探索済み領域・階段・現在位置だけを表示する（未探索は出さない）。
  スライス 3 では 80x22 を 36x8 のブロックに分割し、各ブロックの中心タイルを
  表示する。階段とプレイヤーはサンプリングとは別に座標から上書きするため、
  小さな階段や移動直後の位置が欠けない。モンスター・アイテム・トラップは
  ミニマップに出さない。
- マウス座標は `OnMouse` の `MouseEvent.column/row` からマップ左上のオフセットを
  引いてゲーム座標へ変換する。範囲外・未探索・不可視のセルは無視する。
  ホバーは UI の `Maybe Coord` を更新するだけで、ターンも乱数も消費しない。

### 5.3 サイドバー・HUD

- HP バー、経験値バー、レベル、HP、AC、能力値、所持金、深度、ターン。
- 空腹、状態異常、装備、指輪、武器/防具の強化値。
- 状態異常はアイコン + 短い名前 + 残りターン。色だけに依存しない。
- 数値は原本の情報量を超えない。未識別のアイテム名は外見名のまま。
- セーブ状態、オートセーブ、リプレイ録画中、シードを控えめに表示する。
- サイドバーは折りたたみ可能。クラシック表示では非表示。

### 5.4 メッセージログ

- `TermUI.Widget.LogView` を使う。`StyledText` の `Span` で重要度を色分けし、
  `append` / `extendLast` で追記する。`follow` が末尾追従、スクロール中は止まる。
- 同じメッセージの連続は「×3」のようにまとめる。まとめても Core の
  メッセージ列は変えない（表示だけの最適化）。
- 戦闘、アイテム、システム、警告をフィルタできる。フィルタは `App` の状態で、
  Core のメッセージ列には影響しない。スライス 3 では `F2` で
  all → combat → items → system → warnings を循環する。ワイド表示の
  ヘッダに現在のフィルタ名を出し、クラシック表示では最新メッセージの先頭に
  `[combat]` のように付ける。該当メッセージがない場合はその旨を表示する。
- ログのスクロールバックを開いてもターンは進めない。`LogView.viewer` の
  キーボード/ホイールを使う。スライス 6 ではクラシックの最新メッセージ行、
  ワイドのログ領域でホイールを回すと、ログフィルタを前後に切り替える。
- 長いメッセージは `LogView` が折り返す。`--More--` 的な停止は使わず、
  自動スクロール + 重要メッセージの固定行で代替する。
- 画面外に出たメッセージもログから確認できる。ゲーム状態は変えない。
- ログの高さは `OnResize` で `LogView.resize` に渡す。

### 5.5 インベントリ・アイテム UI

- a-z の表示スロットの一覧。同時所持上限は 23（`MAXPACK`。M2 で実機追確認）。
  選択、詳細、装備、使用、投げる、落とす、比較。
- v1 の一覧は `TermUI.Widget.Select`（文字列の行）を使い、詳細は
  `StyledText` で組む。スタイル付きの一覧が必要になったら、独自の
  `focusable` + `column` に昇格する。
- 未識別名、既知の効果、呪い、強化値、充填数を区別して表示する。
- 装備中の武器・防具・指輪を明示し、比較対象を示す。
- スライス 3 のワイドインベントリは左 68 列に a-z の一覧、右 52 列に
  選択中アイテムの詳細パネルを出す。詳細には表示名、スロット、カテゴリ、
  装備位置、強化値、呪い、既知の杖の充填数、保護状態、同じカテゴリの
  装備中アイテムとの比較を表示する。未識別アイテムは効果を伏せたまま
  外見名だけを出す。選択がない場合は先頭のアイテムを表示する。
- M4 スライス 1 では指輪 2 枠、装備中マーカー、既知の杖の残り充填数、
  未識別の外見名を表示する。`r/z/t/P` は所持品を開いて読み/振る/投げる/
  はめる意図を保持し、選択後に方向プロンプトへ移る。Esc で方向指定を中止できる。
- フィルタ（武器/防具/消費/その他）、ソート、検索。
- マウスで選択、キーボードで完全操作。Esc で閉じる。スライス 6 では
  クラシックの左右 2 列とワイドの 1 列の行クリックで選択し、ダブルクリックで
  既定アクションを実行する。`r/z/t/P` の意図付きで開いた場合は 1 クリックで
  そのアクションを実行する。ホイールは前後の所持品を選ぶ。
- 数量指定（投げる、落とす、買うはない）と方向指定のミニダイアログ。
- 装備変更・使用は 1 ターンを消費する。UI を開くだけでは消費しない。

### 5.6 ヘルプ・コマンドパレット

- `?`/F1 でヘルプ。`TermUI.Widget.MarkdownView` または `LogView` に
  キーバインド、記号、状態異常、基本ルールを表示する。検索は `TextInput`。
  スライス 3 では 80x24 に収まるヘルプを表示し、ワイドでは記号表と
  アミュレットの目標を追加する。Esc、`?`、F1、`q` で閉じる。
- ヘルプは `F2` / `F3` のログフィルタ・テーマ巡回も表示する。
  スライス 9 では実際の `App.Model.keymap` から移動・アイテム・UI の
  キー行を生成する。キーバインドを変えると、ヘルプの表示も同じ変更に
  追従する。
- `Ctrl-P` でコマンドパレット。`TextInput` + `Select` であいまい検索、
  説明、ショートカットを表示する。スライス 11 では 24 項目の一覧を
  上下キー/j/k で移動し、Enter で実行する。M5 スライス 1 で探索を、
  スライス 2 で言語切替を、スライス 3 でアニメーション速度とリプレイ一覧を
  加えて 28 項目になった。各項目は通常の `Msg` を持つため、キーボードと
  同じ更新経路を通る。Esc または `Ctrl-P` で閉じる。
  スコア画面、シード共有、テーマ巡回、アニメーション無効化、言語切替、
  設定の保存・再読み込み、セーブして終了、ロードもパレットから実行できる。
  ヒントは有効なキーマップから生成する。
- コマンドパレットから実行できるのは、通常のコマンドと同じ経路だけ。
- ヘルプ、パレット、スコア、シード共有、インベントリは同時に開かず、
  開いたものが他を閉じる。
- 初回起動時に短い操作ガイドを出す（設定で無効化可能）。
- 下部の F キー表示は `TermUI.Widget.KeyGuide`、メニューは
  `TermUI.Widget.MenuBar` を使う。キーとクリックの定義を二重に持たない。

### 5.7 ダイアログとオーバーレイ

- 確認、アイテム選択、方向選択、数量入力、名前入力、死亡、勝利、戦績。
- termui に Overlay API はない。`absolute` の箱と `focusable` でモーダルを組む。
  ルートの箱はメニューがクリップされない高さにする（`MenuBar` の要件）。
- モーダルはフォーカスを閉じ込め、Esc/キャンセルで安全に戻る。
- 背景のマップは暗いスタイルで表示し、誤操作を防ぐ。
- マウスでボタン、リスト、閉じるボタンを操作できる。スライス 6 では
  ヘルプとスコアはクリックで閉じ、シェア画面はコピー行と閉じる行をクリックで
  操作する。パレットは行クリックで選択、ダブルクリックで実行、ホイールで移動、
  パネル外またはヒント行のクリックで閉じる。
- 死亡・勝利画面では、戦績、死因、深度、ターン、seed を表示する。
  スライス 4 では死亡・勝利の瞬間にスコア画面を自動で開き、そのランを
  メモリ上の戦績一覧の先頭に追加する。スコア画面は `S`、シード共有画面は
  `Ctrl-S` でいつでも開ける。どちらも Esc で閉じる。
- シード共有画面は 16 文字の seed を表示し、`c` または Enter で
  クリップボードへコピーする。同じ seed と同じコマンド列から同じランに
  なることを説明し、`lambda-rogue --seed <seed>` の起動例も表示する。

### 5.8 ビジュアル

- テーマ: Classic CGA、Modern Dark、Amber、Green Phosphor、
  High Contrast、Colorblind Safe、Monochrome。既定は Classic CGA。
- スライス 5 では `LambdaRogue.UI.Theme` に `Theme` と `StyleRole` を置き、
  テーマを `TermUI.Style` の `Indexed` / `RGB` / 属性に変換する。`F3` と
  コマンドパレットの `Cycle theme` で巡回し、変更時は Canvas を同じテーマで
  描き直す。テーマは `App.Model.theme` にだけ存在し、Core、乱数、ターン、
  リプレイ、状態ダイジェストには影響しない。
- `TermUI.Style` は `Default` / `Indexed` / `RGB` を持つ。M5 スライス 3 で
  `COLORTERM` / `TERM` / `NO_COLOR` から色能力を検出し、TrueColor 非対応
  端末では ANSI テーマ、色なしでは Monochrome へ自動フォールバックする。
  `--theme` / `--no-color` / `--no-animation` はこの起動だけ設定を上書きする。
  `--ascii` は未実装で、ゲームのグリフは常に ASCII である。
  現状は選択したテーマの色をそのまま使う。
- 色だけで意味を伝えない。記号、形、太字、下線、ラベルを併用する。
- グリフ:
  - ASCII: 原本に近い `@`, `#`, `.`, `+`, `%`, `!`, `?`, `>`, `$`, `*` など。
  - Unicode: 壁・ドア・階段・トラップを見やすくする。ただし幅 2 の文字は使わない。
- アニメーション:
  - スライス 7 では `UI/Animation.idr` が `Outcome.events` から短命の
    オーバーレイを作る。移動の残像、攻撃の衝撃、ダメージ数字、死亡、
    拾い上げ、ドア、トラップ、レベルアップ、勝利を扱う。
  - 1 フレーム 16ms の固定ティックで年を取らせ、`Every "animation" 16
    AnimationTick` で再描画する。時計や乱数は読まない。
  - 同時に保持するのは最大 24 個。効果はマップの 80x22 にクリップし、
    テーマの `StyleRole` で色を決める。
  - `F4` とパレットの `Toggle animation` で無効化できる。無効時は
    イベントが起きてもオーバーレイを作らない。
  - 移動の補間、投射物の飛翔、視界のフェードはまだない。ゲーム結果・
    乱数・メッセージ順序には影響しない。

| コマンドパレット | なし | `Ctrl-P` |
| ログフィルタ | `F2` | ヘッダから選択 |
| テーマ | `F3` | パレットの `Cycle theme` |
| アニメーション | `F4` | パレットの `Toggle animation` |
| スコア | `S` | メニュー |
| シード共有 | `Ctrl-S` | メニュー |
| 再描画 | `Ctrl-R` / `Ctrl-L` | 自動 |
| 設定 | パレットの `Save settings` / `Reload settings` | 設定ファイルを直接編集 |
| 終了 | `Q` / `Ctrl-C` | メニュー |

- `q` はポーションを飲むキー、`Q` と `Ctrl-C` は終了キーである。
  通常プレイの Esc は終了しない。ヘルプや再生画面の Esc は、その画面を
  閉じるだけである。
- キーバインドは `$XDG_DATA_HOME/lambda-rogue/settings.json`（なければ
  `$HOME/.local/share/lambda-rogue/settings.json`）で変更できる。設定は
  テーマ、アニメーション、キーマップだけを持ち、`Game`、`Replay`、
  `gameDigest` には入らない。詳細は `doc/persistence.md` を参照。
- `r` は巻物を読むキーであり、再描画は `Ctrl-R` / `Ctrl-L` に移した。
  `z`（杖）、`t`（投げる）、`P`（指輪をはめる）、`R`/`T`（外す）は
  所持品を開いて対象を選び、必要な場合だけ方向プロンプトを出す。
- マウス操作はキーボード操作の代替であり、必須ではない。スライス 6 では
  `App.Mouse` が物理座標を純粋に画面レイアウトの座標へ変換し、`OnMouse` が
  既存の `Msg` に変換する。`MouseFocus` は使わず、Canvas は入力を直接持たない。
- マップのクリックは、クリック先へ 1 歩の `Move`（隣接モンスターなら攻撃）に
  なる。プレイヤーのセルにアイテムがあれば拾い、上/下階段なら昇降する。
  方向プロンプト中はクリックした方向で `Zap` / `Throw` を解決する。
  遠くをクリックしても移動は 1 歩だけである。確認なしの階段クリックは
  今後の改善対象。
- ホバーは `HoverCell` で `App.Model.hover` を更新するだけで、ターンも乱数も
  消費しない。termui は通常のホバーを 1002 のボタン・ドラッグ報告としてしか
  受け取らない端末があるため、環境によってはクリック後のドラッグや移動でしか
  更新されない。ウィンドウ座標は `MouseEvent.column/row`（0 始まり、`Len`）で、
  中央寄せレイアウトの左上オフセットを引く。
- インベントリとパレットは `App.Mouse` の座標計算で行・項目を求め、キーボードと
  同じ `SelectItem` / `ActOnItem` / `PaletteSelect` / `PaletteRun` 経路を通す。
  ログ領域のホイールは `CycleLogFilter` / `CycleLogFilterBack` を送る。
- 右クリックはオーバーレイを閉じるためだけに使い、コンテキストメニューと
  長押しはまだない。キーリピート、Esc の 30ms 判定、ペーストは termui の
  挙動を尊重する。

### 5.10 アクセシビリティ

- 完全キーボード操作。マウスなしで全機能に到達できる。
- ASCII モード、色覚多様性テーマ、高コントラスト、アニメーション無効。
- 文字幅は termui の `wcwidth` に従い、日本語・絵文字の幅 2 を正しく扱う。
- ただしゲームのグリフには幅 2 の文字を使わず、セルグリッドを崩さない。
- 画面読み上げは端末依存のため、`--plain` で 1 行 1 イベントのログ出力を用意する。
- UI 言語は英語を初期値とし、`settings.json` の `language` と
  `--lang en|ja`、コマンドパレットの `Switch language` で切り替える。
  日本語カタログを同梱する。
- パレット、スコア、ヘルプの列は `TermUI.Width` の `stringWidth` /
  `charWidth` で端末セル幅を測り、全角文字を含んでも桁を揃える。

## 6. セーブ・リプレイ・戦績

詳細なスキーマ、タイル文字コード、検証規則、ロックと復旧の手順は
`doc/persistence.md` に置く。この節は方針と、Core / UI との境界だけを定める。

### 6.1 セーブ（実装済み）

- JSON スキーマ `lambda-rogue.save.v1`。壊れたセーブは読み込み時に検証し、
  部分的に読まない。失敗したらそのファイルは使わず、次の復旧候補へ進む。
- 保存対象は `Game` の完全なスナップショット: seed、RNG 状態、ターン、
  深度、プレイヤー、訪問済み階層、ラン全体のアイテム、ID 採番、
  識別知識 `knownKinds`、外見表 `appearances`、メッセージ履歴、
  `over`、現在の視界 `visible`。
- 64-bit の seed と 128-bit の RNG 状態は 16 進文字列で保存する。
  `seed` は 16 文字、`rng` は 32 文字（`Rng` の 2 x `Bits64`）。
- トップレベルは `schema`, `kind`, `gameVersion`, `savedAt`, `game`。
  ゲーム状態は `game` の下にまとめ、`seed`, `rng`, `turn`, `depth`,
  `player`, `levels`, `items`, `nextMonsterId`, `nextItemId`,
  `knownKinds`, `appearances`, `messages`, `over`, `visible` を持つ。
  `kind` は `manual` / `autosave`。列挙値は序数ではなく安定した文字列で保存する。
  UI の表示モードは `settings.json` に保存し、セーブには含めない。
- `gameVersion` は実行中の `LambdaRogue.Version.version` と完全一致させる。
  バージョンが違うセーブは読み込まない。
- `levels[]` は訪問済みの階層だけ。`visible` と `explored` は
  448 文字のビットセット hex で保存する。
- `items[]` はラン全体のアイテム。`location` は `floor`（深度と座標）,
  `pack`, `monster`（モンスター ID）のいずれか。`player.inventory` は
  `pack` の ID を所持順に並べたもの。同じアイテムを二重に持たない。
- `tiles` は `Persist/Codec.idr` で固定した 1 文字コードで保存する。
  `Tile` の全構築子（ドアの状態を含む）を一意に表し、未知の文字は
  ロード時に拒否する。文字コードの一覧は `doc/persistence.md` 3.5 節。
- 書き込みは一時ファイル + `fsync` + `rename` のアトミック更新。
  直前のセーブを `.bak` として残す。失敗してもゲームは継続する。
- セーブは 2 種類に分ける。
  - `save.json`: パレットの `Save and quit` による手動セーブ。
    保存に成功したら終了し、次回起動時に読み込んで削除する。
  - `autosave.json`: 10 前進ターンごとと終了時のクラッシュ復旧用。
    正常終了・死亡・勝利・ロード時に削除する。起動時は `save.json` が
    なければ自動で読み込み、成功したら削除する。復旧確認ダイアログはない。
- 手動セーブは 1 つ。死亡・勝利時に `save.json` と `autosave.json` を削除する。
- `session.lock` は PID と起動時刻を持つ。生存中の PID があれば別インスタンス
  として起動を拒否し、死んだ PID や壊れたロックは stale として置き換える。
  正常終了時に自分が持つロックだけを削除する。
- セーブの場所は `$XDG_DATA_HOME/lambda-rogue/`、なければ
  `~/.local/share/lambda-rogue/`。`--data-dir` による上書きは未実装。
  `Persist.Paths` は戦績・リプレイ・設定・セーブに同じルートを使う。
- ロード時はスキーマ、バージョン、範囲、ID の一意性、インベントリ上限、
  RNG の hex 長、床・モンスター参照、状態異常、ID カウンタを検証する。
  検証項目の完全な一覧は `doc/persistence.md` 8.1 節。
- パレットは `Save and quit` と `Load game` を持つ。`Load game` は
  `save.json` を読み、成功したらそのファイルを削除する。起動時の自動再開とは
  別経路で、現在のランを置き換える。

### 6.2 リプレイ

- JSON スキーマ `lambda-rogue.replay.v1`。`seed + 意味的コマンド列 +
  gameVersion` を `.replay.json` に保存する。形式の詳細は
  `doc/persistence.md` 4 節。
- ファイル上のコマンドはプレイ順。`Core.Replay` は記録を O(1) にするため
  新しい順で持ち、`Persist.Replay` が書き込み時に反転し、読み込み時に
  再び反転する。現在の v1 は `seq`、実行前ターン、開始位置、
  チェックポイント、最終結果を持たない。
- キー入力ではなく `Command` の名前と引数（アイテム ID、方向）を保存する。
  キーバインドを変えてもリプレイが壊れない。
- UI のモーダル操作、ログのスクロール、ヘルプ閲覧は記録しない。Core に渡した
  コマンドだけを記録する。不成立だったコマンドも、メッセージ列の再現のために記録する。
- `Core.Replay` は seed と `Command` 列（新しい順）だけを持ち、
  `recordCommand`、`replayCommands`、`runReplay`、`gameDigest`、`replayMatches`
  を提供する。`runReplay` は `newGame seed` からコマンド列を再実行する。
- `gameDigest` は `Game.messages` を除くゲーム状態の FNV-1a 64-bit で、
  16 文字の hex を返す。seed、RNG 状態、ターン、深度、プレイヤー、階層、
  アイテム、ID 採番、識別状態、外見表、終了状態、視界を含む。
  メッセージは表示履歴であり、状態の同一性には含めない。
- App は `runCommand` で `step` に渡したコマンドを記録する。ゲーム終了へ
  遷移した瞬間に一度だけ `replayMatches` を評価し、スコア画面に
  `Replay: verified` または `Replay: MISMATCH` を出す。終了後のコマンドは
  記録も実行もしない。
- ゲーム終了へ遷移した瞬間、`persistRun` が戦績の追記と
  `<seedHex>-<utcSeconds>.replay.json` の保存を行う。タイムスタンプは
  表示・一覧用で、リプレイ内容や `gameDigest` には含めない。
- `replayFromJSON` は `schema` と `gameVersion` の完全一致、16 文字 hex の
  seed、既知のコマンド型・引数を検証する。1 つでも不正ならファイル全体を
  拒否する。
- スコア画面の `P` または `F5` の一覧から可視リプレイを開始する。
  `App.Model.playback` が元のゲームと「閉じたらスコア画面へ戻るか」を保持し、
  表示用のゲームだけを `newGame seed` から `replayCommands` の順に進める。
  記録済みリプレイと元のゲームは変更しない。
- 再生は `Every "replay"` のティックで 1 コマンドずつ進める。速度は
  slow 400ms / normal 200ms / fast 80ms。Space で一時停止、`.`/Enter で
  1 コマンド、`+`/`-` で速度、`R` で最初から、Esc/q でスコア画面へ戻る。
  アニメーションは再生中のイベントにも同じ `Effect` 経路で付く。
- `F5` とパレットの `Replay browser` が保存済みファイルを一覧表示する。
  上下キー・`j`/`k`・ホイールで選択し、Enter またはダブルクリックで再生する。
  一覧は `Persist.Replay.listReplayFiles` の結果を新しい順に表示する。
- 再生中は `Left`/`Right` で 10 コマンドずつ、`Home`/`End` で先頭/末尾へ
  シークする。`seekPlayback` は seed と prefix から `newGame` を再実行して
  決定的に状態を作るため、`Replay` と `gameDigest` は変わらない。
- 途中チェックポイントや状態スナップショットはまだない。各ティックは
  先頭から再生済みの状態をそのまま持ち、終了時に記録した最終状態と
  `gameDigest` で比較できる。シークは毎回 prefix を再実行する。
- 途中から分岐する「what-if」は非目標。必要な場合は状態スナップショットを追加する。

### 6.3 戦績

- 死亡・勝利時にスコアを `scores.jsonl` へ追記する。形式は
  `lambda-rogue.score.v1`（`doc/persistence.md` 7 節）。
- 記録: seed、深度、レベル、経験値、金、ターン、結果（勝利/死亡と死因）。
  名前、殺害数、プレイ日時、ゲームバージョンはまだ持たない。
- 起動時に `Main` が `Persist.Score.loadScores` で履歴を読み込む。
  ファイルは古い順、`App.Model.scores` は新しい順で、スコア画面は
  最大 8 件を表示する。並び替え UI は未実装。死因は `result.cause` に
  保存し、スコア画面の `Cause` / `死因` 列に表示する。
- スコア画面で seed のコピー、リプレイ起動。スコア画面の `P` で
  メモリ上の最新ランのリプレイを可視再生できる。
- シード共有は `seedHex` の 16 文字を `SetClipboard` でコピーする。
  共有画面は現在の深度、レベル、ターン、記録済みコマンド数、リプレイ検証結果も表示する。
- 書き込みは `appendFile` による追記で、`fsync` とロックは未実装。
  同時書き込みは単一プロセス前提。壊れた行は読み飛ばし、警告 UI はまだない。

## 7. テスト方針

### 7.1 Core

- 乱数: 既知の seed に対する `next64` の出力列、`uniform` の範囲と偏り、
  `shuffle` が全要素を一度ずつ返すこと、`stateHex`/`stateFromHex` の往復。
  `fromSeed`/`next64` が rc2base の `mkGen`/`genNext` と一致すること。
- 生成: 1000 seed 以上で「部屋が重ならない」「階段に到達可能」
  「階段・アミュレット・モンスター・アイテムが正しい深度に存在する」。
- 戦闘: 命中・AC・ダメージ・レベルアップの表駆動テスト。
- アイテム: 使用効果、呪い、充填、識別、装備制限。
- ターン: 状態異常の順序、空腹、再生、死亡、勝利。
- セーブ: 保存→ロード→同じ状態、壊れた JSON の拒否、アトミック更新。

### 7.2 リプレイ

- `seed + コマンド列` のゴールデンリプレイを 10 本以上。
- 同じリプレイから同じ `gameDigest`・メッセージ列・最終画面になること。
- 途中でセーブ/ロードしても結果が変わらないこと。
- スライス 4 の `tests/ReplayTest.idr` は、seed hex、記録順、
  `newGame` との一致、手動実行との一致、余分なコマンド・別 seed の不一致、
  digest の決定性、`scoreOf` の未終了/勝利/死亡を検証する。
  10 本のゴールデンリプレイと可視再生は残りの作業。

### 7.3 UI

- termui の `render` + `frameLines` で 80x24 / 120x40 の画面をゴールデン比較。
- マップは `newCanvas` → `drawMap` → `canvas` ノード → `render` の経路で検証する。
  `frameLines` で文字、`getCell` で色・属性まで確認する。
- ダイアログ、インベントリ、ヘルプ、コマンドパレット、リサイズ。
- テーマ: 6 種の一意性、巡回、Classic の既存スタイル一致、マップセルと
  ヘッダのスタイル、テーマ変更がゲーム状態を変えないこと。
- マウス: 80x24 / 100x30 / 120x40 の座標変換、マップクリック、方向
  プロンプト、自分のセルの拾い上げと階段、インベントリ/パレットの行と
  ホイール、オーバーレイの閉じ方、ホバー強調・ツールチップ、ホバーが
  ゲーム状態とリプレイを変えないこと。
- アニメーション: イベント別の効果位置、ダメージ数字の複数セルと
  端でのクリップ、ティックによる消滅、24 個の上限、無効時に効果を
  作らないこと、アニメーション有無でゲーム状態とリプレイが一致すること。
- 可視リプレイ: 開始時の初期状態、1 コマンドずつの進行、一時停止、
  速度変更、再開、完走時の記録状態との一致、終了時の元ゲーム復元、
  再生中にコマンドを記録しないこと。

### 7.4 ファズ・性能

- ランダム seed とランダムコマンドで 10,000 ターン走らせ、クラッシュ・
  不変条件違反・無限ループがないこと。
- マップ + サイドバー + ログの描画を 1 フレーム 16ms 以内（開発機目標）。
- ターン処理は通常 5ms 以内、最悪 20ms 以内。
- セーブは 50ms 以内。超える場合は `RunTask` に逃がす。
- `verify.sh` でビルド、Core テスト、UI スナップショット、リプレイを実行する。
- テストは `tests/TestRunner.idr` にまとめ、`lambda-rogue-tests.ipkg` で
  1 つの実行ファイルにビルドする。rc2 のテストごとのリンクが不安定なため、
  `tests/LambdaRogue` シンボリックリンクと専用の `build/tests` で
  ライブラリとテストを同じソースルートに見せる。

### 7.5 原本との比較

- `doc/rogue-reference.md` に、観測した元ゲームの挙動、データ表、
  計算例、乱数消費の記録を残す。
- 実装と原本の差は「バグ」「意図した現代化」「未確認」に分類する。
- ゲーム性の差はテストで検出できるようにする。UI の差は許容する。

## 8. rc2 / rc2base / termui の現状

### 8.1 結論

M0 の時点で、lambda-rogue の実装を止める上流の必須作業はない。
以前 P0 としていた 2 つは、どちらも idris2-rc2 のツリーに入っている。

| 項目 | 状態 | lambda-rogue での扱い |
| --- | --- | --- |
| termui Canvas | 利用可能（`TermUI.Canvas`） | マップ描画 |
| rc2base 純粋 RNG | `Gen` は利用可能だが抽象型 | アルゴリズムの参照と検証に使用。状態は `Core/Rng` が持つ |
| StyledText / Span / LogView | 利用可能 | ログ、インベントリ詳細、ヘルプ |
| 端末能力検出 | 未提供 | App が環境変数から判定 |
| 64-bit JSON | 未提供 | 16 進文字列で保存 |
| RNG の uniform/shuffle/hex | 未提供 | `Core/Rng.idr` で実装 |

- 上流に追加を要求するのは、複数のアプリで必要になったものだけにする。
  候補は `Xoroshiro128PlusPlus` の `genState` / `genFromState` の 2 関数だけ。
  状態を保存したいアプリ全般に有用だが、lambda-rogue は自前の `Rng` で回避する。
- M1 は termui / rc2base の現在の API だけで開始できる。

### 8.2 termui Canvas（利用可能）

実際の API（`libs/termui/src/TermUI/Canvas.idr`）:

```idris
newCanvas : Len -> Len -> IO Canvas
putCell   : Canvas -> Len -> Len -> Char -> Style -> IO ()
putString : Canvas -> Len -> Len -> Style -> String -> IO ()
fillRect  : Canvas -> (x, y, w, h : Len) -> Char -> Style -> IO ()
clear     : Canvas -> Style -> IO ()
cellAt    : Canvas -> Len -> Len -> IO (Char, Style)
canvas    : Canvas -> Node msg
```

- Canvas は `Buffer` を持つ可変・共有の IO リソース。`newCanvas` は起動時に
  1 回だけ呼ぶ。
- `canvas c` は Canvas のサイズのノード。周囲の `box` の `width`/`height` で
  切り取れる。クリップは Frame と同じ規則。
- 結合文字は持たない。幅 2 の文字は次のセルを continuation にする。
  マップのグリフは幅 1 に限定する。
- スタイルは絶対。`Inherit` は端末の既定色で、親の色は継承しない。
- Canvas は入力を持たない。マップのクリックは `OnMouse`、フォーカスが必要なら
  `focusable` で包む。
- アプリ側の統合:
  - `Main` で `newCanvas 80 22` を作り、初期 `Game` を描いてから
    `runProgram` する。
  - `App.Update` は状態変更後に
    `Perform (drawMap c game >> pure CanvasPainted)` を返す。
  - `App.View` は `canvas c` を返すだけ。`View` の中で `putCell` しない。
  - `drawMap` は `clear` → 可視セルだけ `putCell`。1,760 セルなので
    1 ターン 1 回で十分。
  - 差分描画が必要になったら、前回の `Game` と比較して変更セルだけ描く。
- テストは `newCanvas` → 描画 → `canvas` → `render` → `frameLines` / `getCell`。

### 8.3 rc2base 純粋 RNG（アルゴリズムの参照元）

実際の API（`libs/rc2base/src/System/Random/Xoroshiro128PlusPlus.idr`）:

```idris
export
data Gen = MkGen Bits32 Bits32 Bits32 Bits32   -- s0 high/low, s1 high/low
mkGen        : Bits64 -> Gen
genNext      : Gen -> (Bits64, Gen)
genNextDouble: Gen -> (Double, Gen)
genJump      : Gen -> Gen
genLongJump  : Gen -> Gen
genJumpCE    : Gen -> (c : Bits64) -> (e : Bits32) -> Gen
genJumpN     : Gen -> (n0, n1 : Bits64) -> Gen
```

- 128-bit 状態の xoroshiro128++。`mkGen` は splitmix64 で初期化する。
- **`Gen` は `export data` であり、構築子も状態アクセサも公開されていない。**
  `genNext` で進められるが、128-bit 状態を読み出してセーブに書くことはできない。
- そのため `LambdaRogue/Core/Rng.idr` は、同じアルゴリズムを
  `record Rng (s0, s1 : Bits64)` として純粋に実装する。
  `fromSeed` / `next64` が `mkGen` / `genNext` と一致することを
  `tests/RngTest.idr` で 4 seed x 100 ステップ検証済み。
- ゲーム向けの `uniform` / `roll` / `chance` / `pick` / `shuffle` /
  `stateHex` / `stateFromHex` も `Core/Rng.idr` に置く。
- `stateHex` は 32 文字の小文字 hex（`s0` 16 文字 + `s1` 16 文字）。
  `seed` は 16 文字。
- `genJump` 系は内部で `unsafePerformIO` を使う。ゲームの通常経路では使わない。
  `Core/Rng` も jump は提供しない。
- 原本 Rogue の乱数列との互換は非目標。lambda-rogue 内の再現性だけを保証する。
- 上流への提案は `genState` / `genFromState` の追加だけ。入ったら `Rng` の
  内部を `Gen` に差し替えられるが、M1 は自前実装で進める。

### 8.6 64-bit 整数の JSON 表現（P1 / 回避策あり）

`Language.JSON` の数値は `Double` なので、64-bit の seed や RNG 状態を
数値として保存すると精度が落ちる。ゲーム側では **16 進文字列**として
保存することで回避する。

- `seed`: 16 文字。
- `rng`: 32 文字（`Rng` の 2 x `Bits64`）。
- セーブ/リプレイのスキーマで文字列と長さを検証する。
- 汎用化するなら rc2base に 64-bit 整数ヘルパーを追加するが、M1 では不要。
- 他の rc2 アプリでも必要になったら `Data.Json` 側に昇格する。

### 8.8 rc2 コンパイラ本体について

**必須の追加はない。** 現状の rc2 で、termui を使ったターン制ゲームに
必要な言語機能・FFI・スレッド・シグナル・端末制御は揃っている。
ゲームを実装するうえでの注意点は次の通り。

- `Nat` の `div`/`mod` は遅い（既知）。座標・距離・乱数・ターンは
  `Int32`/`Bits32`/`Bits64` を使う。
- `String` のコードポイント添字は O(n)。ホットパスで 1 文字ずつ
  走査しない。ログは描画時に一度だけ結合する。
- `TermUI.Canvas` は IO なので、`view` を純粋に保つには App 側で描画を
  `Perform` に逃がす（4.1 節）。Canvas を `view` の中で作らない。
- レコード更新やコンストラクタ確保がホットになった場合は、
  まずプロファイルを取る。最適化候補は TODO.md の
  比較融合、アロケータ、Reuse、ループ変換などだが、
  ゲームの前提条件ではない。
- FFI は既存の rc2base（POSIX、termios、時間、乱数、ファイル）で足りる。
  新しい C シムは作らない。
- コンパイル時間が問題になった場合は、インクリメンタルコンパイルと
  モジュール分割で対応する。コンパイラ機能の追加は最後の手段。

ゲームは rc2 の実用的なベンチマークとして使う。プロファイルで
具体的なボトルネックが出たら、再現コード付きで rc2 に Issue を立てる。

### 8.9 追加しないもの

- 音声・BGM。
- 画像プロトコルによるタイル画像。
- ネットワーク対戦・クラウドセーブ。
- WebAssembly/ブラウザ対応。
- 自動探索・自動戦闘。
- 原本にないクラス・スキル・クエスト。

## 10. リスクと未決事項

### 10.1 リスク

- **忠実性の解釈**: Rogue 5.4.4 の細部（乱数消費、AI、視界）は
  ソースをコピーせずに再現する必要がある。観測とテストに時間がかかる。
- **UI の情報漏れ**: サイドバーやツールチップが未識別情報を出さないよう、
  UI と Core の情報境界をテストする。
- **描画性能**: Canvas はあるが、毎ターン全セルを `putCell` すると
  サイドバーやログの再構築と合わせて重くなる可能性がある。M1 で
  80x22 の全描画を測り、必要なら差分描画にする。
- **乱数の忠実性**: 原本の乱数消費順序は再現対象だが、乱数アルゴリズムは
  異なる。lambda-rogue 内の決定論と、行動ごとの確率分布をテストで固定する。
- **端末差**: TrueColor、Unicode 幅、tmux/screen、狭い画面。
  フォールバックとゴールデンテストで吸収する。
- **セーブとパーマデス**: オートセーブが死亡の回避に使われないように、
  セーブ削除のタイミングをテストする。
- **ライセンス**: lambda-rogue は BSD 3-Clause License。原本由来のデータ・
  名称・素材は Rogue の BSD 3-clause に従い、`LICENSE` と
  `doc/rogue-reference.md` 18 章に著作権表示と免責事項を残す。
- **スコープ**: 全 26 階層・全アイテムは大きい。M1 の垂直スライスで
  アーキテクチャを先に検証する。

### 10.2 未決事項

設計方針は 12 節の決定事項ログで固定する。ここには、実装前に観測・判断が
必要なものだけを残す。

- Rogue 5.4.4 の細部: FOV の計算方法、モンスター AI の追跡・逃走・群れ、
  鍵付きドア、秘密のドアの正確な生成確率、罠の作動確率、スコア計算。
- セーブの `tiles` 1 文字コードと、`messages` の保存件数（現案 200 件）。
- リプレイの `gameDigest` をメッセージ列にも拡張するか。現案は状態だけを
  検証し、メッセージ列は別途扱う。
- 端末能力検出と 64-bit JSON は P1。M1 はゲーム側のフォールバックで進める。
- 日本語カタログの訳語レビュー。全 UI キーとメッセージキーは英語・日本語を
  持つが、表現の自然さはスライス 3 以降でも磨く。
